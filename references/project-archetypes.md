# 横向项目论文类型库

## 使用方法

先判断项目最像哪一种论文类型，再决定题目、章节、实验和创新点。不要把所有类型混在一起。

输出时建议给出：

1. 推荐主类型
2. 可兼容副类型
3. 不建议走的类型
4. 原因
5. 对应章节和实验重点

## 类型 1：纯工程系统型

适用项目：

- 后台管理系统
- 业务管理平台
- 数据管理系统
- 可视化平台
- 前后端一体系统

论文主线：

“面向【业务场景】的数据管理与业务协同需求，设计并实现【系统/平台】，通过功能、接口、性能和稳定性测试验证系统可用性。”

章节重点：

- 第三章：需求分析、业务流程、非功能需求
- 第四章：架构设计、数据库、接口、核心模块
- 第五章：功能测试、接口测试、性能测试、稳定性测试

创新点写法：

- 场景化业务流程建模
- 模块化系统架构设计
- 数据管理与异常处理机制
- 工程性能优化与系统验证

高风险：

- 只有页面截图
- 没有性能测试
- 没有本人负责模块
- 题目只有技术栈

## 类型 2：算法应用型

适用项目：

- 图像识别、目标检测、语义分割
- 文本分类、信息抽取、智能问答
- 预测模型、异常检测、推荐系统
- 调度优化、路径规划

论文主线：

“面向【任务场景】中的【识别/预测/检索/决策】问题，设计或改进【方法】，并结合系统实现完成应用验证。”

章节重点：

- 第三章：问题建模、数据来源、数据预处理
- 第四章：模型结构、算法流程、优化策略
- 第五章：对比实验、消融实验、参数实验、效率测试

创新点写法：

- 面向场景的数据处理流程
- 针对任务的模型或策略改进
- 模型与业务系统集成
- 多指标实验验证

高风险：

- 没有数据来源
- 没有 baseline
- 没有评价指标
- 只调用模型 API 却声称算法创新

## 类型 3：AI 应用系统型

适用项目：

- 企业知识库问答
- RAG 系统
- 大模型智能助手
- 文档理解平台
- 智能客服、智能运维助手

论文主线：

“面向【知识管理/业务问答/文档检索】场景，构建基于【RAG/大模型/语义检索】的智能应用系统，通过问答效果评估和系统测试验证应用效果。”

章节重点：

- 数据处理：文档清洗、切分、向量化、索引
- 方法流程：检索、重排、上下文构建、生成、引用溯源
- 系统实现：知识库管理、问答服务、权限、后台
- 实验验证：检索命中率、答案相关性、引用准确性、响应时间

创新点写法：

- 适配企业私有知识场景的问答流程
- 检索、生成和来源追溯的集成机制
- 业务系统与大模型能力的工程化落地

高风险：

- 把 prompt 工程写成理论创新
- 没有问答评价集
- 没有引用来源验证
- 不说明模型和数据边界

## 类型 4：机器人系统型

适用项目：

- 移动机器人巡检
- 机械臂作业
- AGV 调度
- 机器人导航、避障、控制
- 感知、决策、控制系统集成

论文主线：

“面向【机器人任务场景】，设计包含【感知/决策/控制/调度】的机器人系统，并通过仿真或真实场景实验验证任务执行效果。”

章节重点：

- 第三章：任务场景、硬件组成、系统架构
- 第四章：路径规划、任务调度、控制策略、通信机制
- 第五章：路径长度、到达时间、定位误差、控制误差、完成率、稳定性

创新点写法：

- 面向具体场景的任务流程建模
- 任务调度与路径执行策略
- 机器人端与后台端集成
- 场景实验验证

高风险：

- 只有演示视频没有数据
- 没有误差和完成率指标
- 仿真实验写成真实部署
- 个人工作量不清

## 类型 5：数据平台型

适用项目：

- 采集平台
- 数据治理平台
- 监控平台
- 日志分析平台
- 报表平台

论文主线：

“面向【业务数据管理】需求，设计数据采集、清洗、存储、分析和可视化流程，并通过数据质量、查询性能和系统测试验证平台有效性。”

章节重点：

- 数据源与数据流程
- 数据清洗与质量控制
- 数据库和索引设计
- 查询、统计、可视化
- 数据一致性、响应时间、吞吐量

创新点写法：

- 多源数据处理流程
- 数据质量控制机制
- 场景化统计分析与可视化
- 查询性能和稳定性优化

高风险：

- 只做 CRUD
- 数据流程不清
- 没有数据质量或性能指标
