# 常见反例与安全改写

用这个文件检查输出是否会被导师、盲审或答辩老师质疑。不要只指出问题，要给出更稳的改写方式。

| 反例 | 风险 | 更稳写法 |
| --- | --- | --- |
| 基于 SpringBoot 和 Vue 的某管理系统设计与实现 | 像课程设计或项目说明书，研究问题弱 | 面向某业务场景的多源数据管理与流程优化系统设计与实现 |
| 本文提出一种全新的智能算法 | 过度创新，容易被追问算法新在哪里 | 本文结合场景约束对既有方法进行适配与工程优化 |
| 系统显著提升企业效率 | 没有量化证据 | 通过流程耗时、响应时间或人工步骤数对比评估系统效果 |
| 本人参与完成整个项目 | 本人工作量边界不清 | 本人主要负责数据处理、检索接口、实验评估和部署联调 |
| 实验结果表明系统效果很好 | 空泛，缺指标 | 实验从准确率、响应时间、吞吐量、异常处理成功率等指标验证 |
| 该项目适合冲击 Nature | 对普通横向项目明显过高 | 当前更适合国内硕士论文或 EI 工程应用，Nature 仅可作为叙事训练参考 |
| 甲方数据证明了模型有效 | 保密和复现风险 | 使用脱敏样例、公开替代数据或统计指标描述验证过程 |

## 输出前自检

- 有没有把功能列表当成研究内容？
- 有没有把“实现了”写成“提出了”？
- 有没有没有证据的效率提升、准确率提升或上线效果？
- 有没有忽略本人负责边界？
- 有没有给出过高路线推荐，例如把普通工程项目推荐为 CCF-A/CVPR/Nature 主路线？

## 降风险句式

```text
当前材料更适合写成“工程应用型硕士论文”，不建议直接强调重大理论创新。可以把贡献表述为场景建模、系统集成、流程优化和可验证实验。
```

```text
该结论目前只能作为待验证 claim，建议先补充测试记录、对比基线和脱敏样例，再写入论文结论。
```
