# AI 应用系统示例

## 示例主题

基于大模型的企业知识库问答系统设计与实现

## 原始项目描述

企业内部存在大量制度文档、产品资料、运维手册和历史工单。员工查询资料主要依赖人工搜索和同事咨询，存在检索效率低、答案来源不清、知识更新滞后等问题。项目目标是建设一个企业知识库问答系统，支持文档上传、文本切分、向量化检索、大模型问答、答案引用展示、用户权限管理和后台维护。

用户本人负责的内容包括：知识库文档管理、文本切分与向量入库、检索增强生成流程、问答接口、后台管理模块和系统测试。

## 可转化论文题目

1. 稳健型：基于大模型的企业知识库问答系统设计与实现

3. 算法方法型：基于检索增强生成的企业知识问答方法研究与系统实现
4. 系统设计型：面向企业文档检索与问答的知识库平台设计与实现
5. 导师容易接受型：企业知识库问答系统的设计、实现与应用验证

## 研究问题

面向企业知识管理场景中文档分散、查询效率低和答案来源难追溯等问题，研究并设计一种基于检索增强生成的企业知识库问答系统，以提升内部知识检索效率、答案可解释性和系统可维护性。

可拆解为：

- 如何将企业非结构化文档转化为可检索的知识单元？
- 如何结合向量检索与大模型生成提升问答相关性？
- 如何在系统层面实现文档管理、权限控制、问答服务和结果溯源？
- 如何通过实验和测试验证系统的有效性与可用性？

## 主要研究内容

1. 企业知识库问答场景需求分析与任务建模  
   依据来源：来自真实项目。分析企业文档管理、资料查询、权限控制和问答结果展示等业务流程，明确系统功能需求与非功能需求。

2. 基于检索增强生成的问答流程设计  
   依据来源：来自算法改进。围绕文档切分、向量表示、相似度检索、上下文构建和答案生成设计完整处理流程。

3. 企业知识库问答系统架构与模块实现  
   依据来源：来自系统集成。实现文档上传、知识库管理、问答接口、引用展示、用户权限和后台管理等模块。

4. 问答效果评估与系统性能测试  
   依据来源：来自实验验证。通过检索命中率、答案相关性、响应时间、并发能力和功能测试验证系统效果。

## 创新点或特色

1. 面向企业知识管理流程构建了文档入库、语义检索、问答生成和引用展示的完整任务链路，增强了系统在实际业务场景中的适用性。
2. 针对企业文档内容长、格式复杂和答案来源需追溯的问题，设计了结合文本切分、向量检索和来源标注的问答流程。
3. 完成了知识库管理、问答服务与后台维护模块的集成，并通过功能测试和性能测试验证系统可用性。

## 实验设计

算法与问答效果：

- 对比实验：比较关键词检索、向量检索、RAG 问答三种方案的检索相关性和回答质量。
- 消融实验：比较不使用引用片段、不同文本切分长度、不同 Top-k 检索数量对回答效果的影响。
- 参数实验：测试 Top-k、相似度阈值、chunk size 对回答准确性和响应时间的影响。
- 评价指标：Recall@k、Top-k 命中率、人工相关性评分、答案可追溯率、平均响应时间。

系统测试：

- 功能测试：文档上传、知识库管理、问答查询、答案引用、权限管理、后台维护。
- 接口测试：文档入库接口、问答接口、用户接口、知识库查询接口。
- 性能测试：平均响应时间、最大响应时间、QPS、并发用户数、CPU 和内存占用。
- 稳定性测试：连续问答、多轮文档更新、异常文档上传、空检索结果处理。

## 风险点

- 如果没有真实企业数据，需要说明测试数据来源，不能虚构内部数据规模。
- 如果没有人工标注问答集，需要补充小规模评价集或说明采用人工评估方法。
- 如果没有上线部署，不能写“已在企业全面应用”，应写“完成原型系统验证”或“在模拟业务流程中验证”。
- 创新点应聚焦 RAG 流程设计、系统集成和工程优化，避免夸大成大模型理论创新。
