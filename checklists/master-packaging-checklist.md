# 横向项目转论文总检查清单

## 选题

- [ ] 题目包含具体场景。
- [ ] 题目包含系统、方法、平台或任务对象。
- [ ] 题目没有过度夸大。
- [ ] 题目不是单纯技术栈堆叠。
- [ ] 有 3 到 5 个备选题目。

## 研究问题

- [ ] 已从业务需求提炼技术痛点。
- [ ] 技术痛点可以通过系统、算法、数据处理或控制策略解决。
- [ ] 有一句话研究问题。
- [ ] 研究问题不是单纯“做一个系统”。

## 本人工作量

- [ ] 明确本人负责模块。
- [ ] 明确团队其他成员负责内容。
- [ ] 本人负责模块能展开成论文章节。
- [ ] 有代码、接口、实验或文档支撑。

## 研究内容

- [ ] 有 3 到 4 条研究内容。
- [ ] 每条研究内容有依据来源。
- [ ] 没有把功能列表直接当研究内容。
- [ ] 每条内容都能对应章节。

## 创新点或特色

- [ ] 控制在 2 到 3 条。
- [ ] 使用“主要特色”或“主要工作”更稳。
- [ ] 没有虚构理论创新。
- [ ] 没有虚构上线效果。
- [ ] 每条都有证据支撑。

## 实验与测试

- [ ] 纯系统项目有功能、接口、性能、稳定性测试。
- [ ] 算法项目有数据、指标、baseline、对比实验。
- [ ] 算法项目尽量有消融实验。
- [ ] 机器人项目有路径、误差、完成率或稳定性指标。
- [ ] 实验结论没有超出数据范围。

## 论文结构

- [ ] 第一章能引出研究问题。
- [ ] 第二章不是教材式技术介绍。
- [ ] 第三章有需求和架构。
- [ ] 第四章体现本人核心工作。
- [ ] 第五章有证据链。
- [ ] 第六章总结与研究内容对应。

## 风险

- [ ] 没有虚构数据。
- [ ] 没有虚构实验。
- [ ] 没有虚构部署。
- [ ] 没有把团队工作全部写成个人工作。
- [ ] 参考文献真实可查。
