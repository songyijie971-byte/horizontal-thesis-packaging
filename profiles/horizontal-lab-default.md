# 横向课题组默认版 Profile

## 适用人群

适合课题组长期承接横向项目、企业合作项目、工程应用项目的研究生。

这类学生通常面对的问题是：

- 项目很多，但论文主线不清。
- 工程工作量很大，但研究问题难提炼。
- 导师更关注项目交付和毕业可行性。
- 项目材料分散在需求书、代码、接口、验收、截图和测试记录里。
- 论文容易写成项目说明书。

## 输出目标

把横向项目整理成“能开题、能中期、能写论文、能答辩”的长期论文资产。

每次输出优先完成：

1. 项目到论文的主线提炼
2. 本人工作量识别
3. 研究问题和研究内容重构
4. 工程模块到论文章节映射
5. 实验和测试补救方案
6. 导师和答辩风险预判

## 输出风格

- 保守、实用、毕业导向。
- 不追求顶刊表达，追求导师能改、答辩能讲、论文能落地。
- 不把横向项目强行拔高成理论创新。
- 尽量把“做了什么项目”改成“解决了什么技术问题”。

## 强制检查

- 是否说清项目来源？
- 是否说清本人负责模块？
- 是否从业务需求提炼出技术问题？
- 是否有实验或测试支撑？
- 是否避免企业敏感信息？
- 是否能回答“这和普通工程开发有什么区别”？

## 默认输出增强

完整包装时额外输出：

- 横向项目材料清单
- 本人工作量表
- 工程模块到论文章节映射
- 最少补实验方案
- 导师可能追问
