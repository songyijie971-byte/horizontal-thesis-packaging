# 项目 Intake 表单模板

## 使用场景

当用户第一次提供横向项目、企业项目、导师任务、项目代码结构、验收材料或一段很乱的项目描述时，先用本表抽取信息。

不要要求用户一次性补齐所有内容。先根据已有材料填写，缺失项标注“待补充”。

## Intake 表

| 字段 | 提取结果 | 状态 |
| --- | --- | --- |
| 当前阶段 | 选题 / 开题 / 中期 / 论文 / 答辩 / 不确定 | 已知/待补 |
| 项目来源 | 横向项目 / 企业合作 / 导师任务 / 实习项目 / 实验室项目 | 已知/待补 |
| 应用场景 | 行业、对象、业务流程、使用环境 | 已知/待补 |
| 原始业务需求 | 甲方或导师要解决什么问题 | 已知/待补 |
| 技术痛点 | 效率、准确率、稳定性、实时性、集成度、维护性等 | 已知/待补 |
| 本人负责模块 | 用户本人做了哪些模块、实验或文档 | 已知/待补 |
| 团队其他工作 | 其他成员或已有系统做了什么 | 已知/待补 |
| 技术路线 | 前后端、数据库、模型、机器人、通信、部署 | 已知/待补 |
| 数据来源 | 真实数据、公开数据、模拟数据、仿真数据、日志数据 | 已知/待补 |
| 已有成果 | 代码、系统、截图、测试、论文草稿、PPT | 已知/待补 |
| 可做实验 | 功能、性能、接口、对比、消融、场景验证 | 已知/待补 |
| 不能公开内容 | 企业名称、数据、截图、接口、内部指标 | 已知/待补 |
| 最大风险 | 创新不足、实验不足、工程味重、数据不清、工作量不清 | 已知/待补 |
| 目标产物 | 题目、开题、中期、论文目录、实验、答辩 PPT | 已知/待补 |

## 自动判断

根据 intake 表输出：

1. 推荐主 profile
2. 推荐副 profile
3. 论文包装类型
4. 当前最缺的 3 个材料
5. 立即可写的内容
6. 暂不建议写成结论的内容

## 缺失材料提问规则

优先问最关键的 3 个问题，不要一次问十几个。

优先级：

1. 你本人负责哪些模块？
2. 数据从哪里来？
3. 现在有哪些实验或测试结果？
4. 系统是否真实部署或只是测试环境？
5. 导师目前最担心什么？
