# 下一步引导模板

每次完成主要回答后使用。目标是让用户知道“现在该怎么继续”，但不要替用户自动执行下一步。

## 输出规则

- 给 2-4 个选项，按当前阶段排序。
- 每个选项用一句话说明用途。
- 如果涉及下游论文 skill，说明“已安装可继续交接；未安装可用 find-skills/找技能查找或安装”。
- 如果项目是 C/D 类，优先引导补证据、重构主线或换题，不要急着推荐下游写作。
- 如果用户已经明确下一步，就只确认并执行用户指定任务，不再追加很多选项。
- 不要每次都问是否建立记忆；只在一次完整蓝图、开题、实验或答辩任务完成后作为可选项出现。

## 通用句式

```markdown
下一步你可以选一个方向：

1. 补关键证据：我可以按“最该补的 3 个材料”给你列一张一周内可完成的补证据清单。
2. 生成交接包：我可以把本次结果整理成 sciskill / ei / ccfb / sci / cvpr / natureskill 可接着用的论文转化交接包；如果没有对应 skill，可以先用 find-skills/找技能查找或安装。
3. 模拟导师追问：我可以按严导师口径问你 8-10 个最可能被追问的问题，并给安全回答。
4. 进入开题/正文/答辩：你告诉我目标，我把蓝图改成开题报告、论文章节或答辩 PPT 大纲。
```

## 按结论分流

### A/B 类

优先建议：

1. 补证据清单。
2. 生成下游交接包。
3. 开题、正文或答辩材料。
4. 导师追问模拟。

### C/D 类

优先建议：

1. 补当前项目内部证据。
2. 重构为局部技术问题。
3. 判断是否换题或争取更核心模块。
4. 暂不推荐直接进入论文正文写作。

## 示例

```text
下一步建议：你这个项目目前是 B 类，我建议先做“补证据清单”。如果你想继续写开题，我也可以先生成论文转化交接包；已安装 sciskill/sci skill 就能继续交接，没安装的话可以用 find-skills/找技能查找。
```
