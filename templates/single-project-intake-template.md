# 单项目最小输入模板

用于第一次判断“一个横向项目能不能单独转成一篇硕士论文”。用户材料不足时，优先让用户补这个最小表，而不是一开始要求完整开题信息。

## 给用户的最小问题

```markdown
请先按下面 8 项补充。能写多少写多少，不确定就写“不确定”。

1. 项目一句话：这个项目是给谁用、解决什么问题？
2. 项目规模：大概有哪些模块？是完整系统、核心模块，还是小功能/小脚本？
3. 本人负责：你具体负责哪些代码、模块、算法、接口、测试、部署或文档？
4. 技术路线：用了哪些关键技术？前后端、数据库、算法、模型、机器人、通信、部署等。
5. 数据/场景：有没有真实数据、日志、公开数据、仿真、企业案例或测试样例？
6. 已有证据：有没有代码、截图、接口文档、测试表、实验结果、提交记录、演示视频？
7. 可验证点：你觉得能做哪些测试或实验？功能、性能、对比、消融、场景验证等。
8. 限制条件：是否涉密？能否脱敏？距离开题/中期/论文/答辩还有多久？
```

## 输出要求

- 先区分“已确认事实”“推测内容”“缺失信息”。
- 不要替用户编企业背景、数据、实验结果或本人工作量。
- 如果缺失信息不影响初判，可以先给 A/B/C/D 初判，并标注“低置信度”。
- 如果缺失信息会直接影响结论，先只问最关键的 3 个问题。
