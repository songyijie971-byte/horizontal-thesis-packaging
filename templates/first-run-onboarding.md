# 渐进式个性化 Onboarding 模板

## 触发条件

不要在用户第一次贴项目时强制使用本模板。第一次使用默认先用 `templates/single-project-intake-template.md` 判断单一项目能不能转论文。

只在以下情况使用：

- 用户明确说“建立本地个性化配置”“以后记住我的偏好”“按我的学校/导师长期使用”；
- 用户完成一次论文转化蓝图后，同意把可复用偏好写入本地记忆；
- 任务进入开题、论文格式、答辩风险等阶段，且学校/导师口径会明显影响输出；
- 已有 `CUSTOMIZE.local.md`、`memory/user-context.md` 或 `profiles/local/*.md`，用户要求读取或更新。

## 目标

用最少问题建立可用的本地个性化配置，让后续输出更贴合用户学校、导师、项目和毕业风险，同时不把首次使用变成填表。

## 个性化最小问题

只问 5 个问题：

1. 你现在处于哪个阶段：选题、开题、中期、论文初稿、盲审、答辩？
2. 你的项目最像哪类：纯工程系统、AI 应用、算法应用、机器人系统、数据平台、企业保密项目？
3. 你本人主要负责哪些模块或实验？
4. 你导师更在意什么：稳妥毕业、创新点、实验数据、工程落地、论文规范、答辩表达？
5. 你现在最担心什么：太工程、创新不足、实验不足、数据不能公开、本人工作量说不清、答辩被追问？

## Agent 行为

用户回答后，生成：

1. 建议写入 `CUSTOMIZE.local.md` 的内容；
2. 建议写入 `memory/user-context.md` 的内容；
3. 推荐 profile 组合；
4. 下一次默认使用的输出风格。

如果当前环境允许编辑文件，也必须先征得用户确认，再写入本地文件。
如果不允许编辑文件，输出可复制内容。

只记录可复用偏好，不记录企业真实名称、导师真实姓名、未脱敏数据、项目内部地址、论文原文或答辩记录。

## 输出模板

```markdown
## 是否建立本地论文包装记忆

本次项目已经完成初步判断。为了以后少问重复问题，我可以为你建立一份本地偏好记忆。只记录风格和规则，不记录企业隐私和原始数据。

如果你愿意，请补充 5 个信息：

1. 当前阶段：
2. 项目类型：
3. 本人负责：
4. 导师最在意：
5. 最担心的风险：

回答后我会生成建议写入 `CUSTOMIZE.local.md` 或 `memory/user-context.md` 的内容。写入前会再次让你确认。
```
