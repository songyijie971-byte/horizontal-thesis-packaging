# 端到端样例：工程味太重项目救火

## 用户原始输入

老师说我的论文太像项目说明书。我写了很多页面功能，比如登录、用户管理、数据列表、导入导出、统计图、权限控制。第五章现在只有几张截图。我不知道怎么改。

## 诊断

最大问题不是项目不能写，而是表达方式不对：

- 功能罗列太多。
- 技术问题不清。
- 章节像验收文档。
- 第五章缺少测试证据。
- 创新点不宜写太高。

## 推荐 profile

1. `profiles/engineering-heavy.md`
2. `profiles/graduation-first.md`
3. `profiles/advisor-strict.md`

## 重构方式

### 功能改写

| 原功能 | 论文表达 | 证据 |
| --- | --- | --- |
| 登录、权限 | 用户权限管理与业务流程控制 | 权限测试 |
| 数据列表 | 业务数据管理与查询机制 | 查询响应时间 |
| 导入导出 | 数据交换与批量处理流程 | 文件处理测试 |
| 统计图 | 状态可视化与统计分析模块 | 场景流程测试 |
| 告警 | 事件驱动异常处理机制 | 告警响应时间 |

### 第五章补救

1. 功能测试表：覆盖核心业务流程。
2. 接口测试表：覆盖正常和异常请求。
3. 性能测试表：响应时间、并发、CPU、内存。
4. 稳定性测试：连续运行或重复任务。
5. 场景案例：完整业务流程从输入到输出。

## 安全创新点

建议写“主要特色”：

1. 面向【场景】构建了完整业务流程和数据管理机制。
2. 设计了模块化系统架构，实现权限、数据、统计和异常处理的协同。
3. 通过功能、接口和性能测试验证系统可用性。

## 不能再写

- “本系统显著提升效率”，除非有量化对比。
- “提出创新算法”，如果只是工程功能。
- “系统已经稳定上线”，除非有部署记录。
